# Sources

Every factual claim on this site has a line here: what is claimed, where it came
from, and when it was last checked. If a claim has no line, it should not be on
the site.

**Why this file exists.** Readers plan a year of their life around these facts.
A wrong claim here is not a bad look, it is real damage. This file makes a wrong
claim findable instead of invisible.

## Status key

- **VERIFIED** — read on the primary source named
- **SECONDARY** — from a reliable report, not the primary source itself
- **OPEN** — asked, awaiting an answer. Must not be stated as settled on the site.
- **READER REPORTS** — what people who wrote to us said happened to them, with
  their permission to publish it. The weakest grade here, and deliberately so:
  it is evidence of what people are being told and charged, never evidence of
  what the rules are. A statute, an authority or a primary document outranks it
  every time, and where it contradicts one, the page says so. It goes on the
  site only as a count over a stated period, never as one person's story
  presented as fact.

| --- | --- | --- |
| 404, 410, DNS failure, refused connection | **Dead — fails the run, opens an issue** | The page has genuinely gone |
| 401, 403, 405, 406, 429, 5xx, timeout | **Warning only — never fails** | Bot protection or a server wobble, not link rot |

This distinction is not theoretical. `frankfurt.de` answers **403 to
command-line requests** while serving the page normally to a browser. Treating
that as a dead link would have produced a false alarm on the single most-cited
authority page on the site.

Two further guards against noise: the checker sends a real browser User-Agent
(which is what gets `frankfurt.de` to answer 200), and every failure is retried
once after 1.5 seconds before being believed.

### How the notification works

On failure it opens a GitHub issue labelled `link-rot`, titled "Link check: a
cited source has gone", listing each dead URL **and which pages cite it**. If an
issue is already open it comments instead of opening a duplicate. When the links
resolve again it comments and closes the issue — so an open `link-rot` issue
always means something is broken *right now*. GitHub emails on both the issue and
the failed run.

### Verified, not assumed

The failure path was tested against a fixture containing a real 404, a
non-existent domain, a broken internal link and a missing image. All four were
caught, `mailto:` and `#fragment` links were correctly skipped, and the run
exited 1. The passing path exits 0.

### Known limitation

GitHub disables scheduled workflows in a repository after 60 days with no commit
activity. A site that is finished and correct could therefore go quiet exactly
when nobody is watching it. GitHub emails the owner when this happens; any commit
or a manual "Run workflow" revives it.

**Deliberately separate from `deploy.yml`** so that a flaky external site can
never block publishing.

`/contact/` now carries a structured form: what it is about, which page, the

| --- | --- |

non-commercial, and the alternatives cost more than the risk.

## The link checker was crying wolf, 2026-08-27

The 24 August run failed and opened issue #1, naming eight dead
`gesetze-im-internet.de` links — §§ 2, 5, 16a, 29, 30, 32, 68 and 81a. **None of
them were dead.** All eight answer 200; GitHub's runners could not reach the host
and undici reported `UND_ERR_CONNECT_TIMEOUT`.

`scripts/check-links.mjs` was treating every network error except its own abort
as a dead link. Now only `ENOTFOUND` — a domain that no longer resolves — counts
as dead at the network level; timeouts, resets and refusals are warnings. The
reasoning is in the code: a missed dead link costs a week, because the run
repeats on Monday and a page that has genuinely gone answers 404 rather than
hanging, while a false alarm costs the checker, because nobody reads the third
one.

Two further faults found while testing, both the same defect pointing the other
way — a link reported **ok** that was not:

- Statuses outside a hard-coded list fell through to "ok". The new Nds. ministry
  link was reported as `ok 400`. Anything at 400 or above that is not 404/410 is
  now *unconfirmed*.
- HEAD was trusted too readily. That ministry URL answers HEAD with a 303 that
  redirects to a 400, and GET with the page. The GET fallback now runs for any
  non-definitive status, which also cleared the standing frankfurt.de (403) and
  instagram.com (429) warnings.

Local run after the fix: 41 links, no dead, two unconfirmed — facebook.com,
which refuses bots, and setopati.com, which was slow. Issue #1 closes on the next
green run.

**A guard against the opposite failure.** Because unknown network errors are now
warnings, a runner with no working network would warn on everything and report a
clean bill of health. If more than half the links are unconfirmed, the report now
says the run is inconclusive instead of passing quietly.

## Reader reports become a source — 2026-09-23

**What changed.** The contact form now carries one optional tick box: *you may
publish this*. Unticked — the default — a message is private and is used only to
check and correct our own pages. Ticked, it may be published, without the
sender's name, email address, or anything that identifies them.

An invitation to write in now appears at the foot of every content page rather
than only on the contact page. The imprint, the privacy page and the contact
page itself are excluded.

**Why a new status grade rather than SECONDARY.** SECONDARY means a reliable
report of a primary source — an IHK explaining a statute. What a reader tells us
is a different kind of thing: it is testimony about what happened to one person,
and it cannot be checked against anything. Filing it as SECONDARY would put an
anecdote on the same footing as a chamber's published guidance, which is exactly
the confusion this file exists to prevent.

**The rule for putting reader reports on the site.** They go up as counts over a
stated period, never as one story presented as a fact:

> Reader reports: 14 quotes received between September 2026 and February 2027,
> range NPR 7–16 lakh, median 11.

That is defensible, it is honest about what it is, and nobody can be identified
from it or retaliated against for it. Individual accounts published in their own
words are a separate decision and are not authorised by the tick alone.

**What is never published, tick or no tick.** The name of the sender. The name
of any institute, agent, official or private person the sender names — a tick
gives consent about the sender's own words, not about a third party who has had
no say and no chance to answer. This site gives readers questions to ask, not
accusations to repeat, and that does not change because the accusation now
arrives by email.

**What still has to happen before the first reader report goes on a page.** The
count needs a line in this file like any other claim, carrying the period it
covers, the number of reports behind it, and the READER REPORTS grade. A figure
with no line does not go on the site, and that rule has no exception for figures
that came from readers.

**Consent is withdrawable.** Anyone who ticked the box may write and have the
material removed, for no reason, at any time. The privacy page says so and
carries the Art. 7 (3) GDPR position.

### CORRECTION, before publication — my own reading of the fee rule was wrong

During Phase 1 I reported, on the strength of law-firm summaries, that the Single
Permit Directive contained a Europe-wide equivalent of § 296a SGB III. On reading
Article 10 in the Official Journal, that is **not** what it says:

> *"Where fees for processing applications are paid by the employer, the employer
> shall not be entitled to recover such fees from the third-country national."*

That governs **the government fee for processing a permit application** and
nothing else. It says nothing about a private agent's placement fee. The page
therefore states it narrowly — it makes "we will pay the permit fee and take it
out of your wages" unlawful across the EU, and that is all it does.

**The actual Europe-wide cousin of § 296a is Article 13(10) of the Talent Pool
Regulation**, which does name private employment agencies and does cover money
taken after placement as well as before. Article 15 of the directive expressly
preserves more favourable national rules, so § 296a is untouched either way.

This is recorded because the wrong version was nearly published on a secondary
source. It was not, and the reason it was not is the rule in this file.

## Net rather than gross, and a source that does not exist — 2026-10-16 (same day, third revision)

Alan asked whether the table should show net rather than gross. It should, and
it now does. Getting there turned up a gap worth recording.

### There is no official net minimum wage table for Europe

| Claim | Source | Status | Checked |
| --- | --- | --- | --- |
| Eurostat publishes the minimum wage **gross only** | Eurostat `earn_mw_cur`, methodology note: figures are *"before tax and social security contributions payable by the employee are deducted"* | **VERIFIED — primary** | 2026-10-16 |

Its footnote *"Estimated, as the minimum wage is set as a net wage"* marks countries that **set** their minimum wage as a net amount, so WSI estimates the gross — the opposite of what was wanted | WSI Report No. 111e, read in full | **VERIFIED — read directly** | 2026-10-16 |
| OECD *Taxing Wages 2026* uses 67%, 100% and 167% of the average wage, not the minimum wage | OECD Taxing Wages 2026 | **SECONDARY** | 2026-10-16 |

So the net figure had to be computed, or not published. We computed it, and the
page says in terms that we computed it.

### Method, and why the error runs one way

**approximate net = gross minimum wage × (1 − deduction rate)**, where the
deduction rate is Eurostat's own income tax plus employee social contributions
for a single person without children at 50% of average earnings.

The weakness is that the two series are measured at different wage levels. We
checked how far apart they are, comparing twelve times the monthly minimum wage
against Eurostat's gross at the benchmark:

| Croatia | Poland | Germany | Portugal | Greece | Romania | Bulgaria | Cyprus | Malta |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1.02 | 1.01 | 0.97 | 0.93 | 0.87 | 0.83 | 0.80 | 0.75 | 0.73 |

Where the ratio is near 1 the rate transfers cleanly. Where the minimum wage
sits **below** the benchmark, the income tax component would be smaller in
reality because of tax-free allowances — so **the estimate errs towards showing
too little kept, never too much.** Social contributions, which dominate in every
one of these countries, are flat percentages and transfer either way. In Cyprus
and Portugal the income tax component is already zero at the benchmark, so only
contributions apply and those two figures are solid.

Every figure is **rounded to the nearest €5** so it cannot be mistaken for a
published number. All of this is stated on the page, not just here.

| Claim | Source | Status | Checked |
| --- | --- | --- | --- |
| Approximate monthly net minimum wage: Germany ~€1,665, Cyprus ~€965, Portugal ~€955, Greece ~€875, Malta ~€860, Poland ~€840, Croatia ~€805, Romania ~€490, Bulgaria ~€480 | Our arithmetic on Eurostat `earn_mw_cur` (2026-S2) and `earn_nt_net` (2025) | **SECONDARY — our calculation on official inputs, labelled as approximate on the page, rounded to €5** | 2026-10-16 |

### Why the switch mattered more than expected

**Net changes the order, it does not just shrink the numbers.** On gross pay
Poland is the second best country on the page. On net it is **sixth**. Romania
keeps about 59% of gross while Portugal and Cyprus keep about 89%, so the real
gap between Romania's €825 and Portugal's €1,073 is far wider than it looks.
A reader comparing two offers on gross pay would have got this wrong, which is
exactly the kind of error this page exists to prevent.

### One place the net conversion was deliberately NOT applied

The Ausbildung comparison stays **gross against gross**, and says so. The
deduction rate used elsewhere includes income tax, and an apprentice on €724 a
month sits below the German tax-free allowance, so applying that rate would
overstate what comes off and understate the apprentice's position. We could
compute a contributions-only figure, but we have not verified German apprentice
contribution rates, so we have not. The page states the limitation rather than
quietly using the wrong rate.

**Correction to the previous entry.** The "so which country leaves you better
off" passage originally quoted 2,164 against 1,317 — the **gross** purchasing
power figures — while the table beside it had switched to net. A reader would
have looked for those numbers and not found them. Now updated to the net
figures throughout: about €1,665 against about €490, and 1,540 against 780.

## Phase 3: the figures now check themselves — 2026-10-29

The Europe page rests on numbers that move on a schedule and announce nothing.
Minimum wages change twice a year, tax and social contribution rates once. A
dead link gets caught by `check-links`; a reworded government page gets caught
by `check-watch`; a figure that quietly became last year's figure was caught by
nothing.

`scripts/check-figures.mjs` closes that gap, and a monthly workflow runs it.

### What it reads

| Source | Dataset | What it gives |
| --- | --- | --- |
| Eurostat dissemination API | `earn_mw_cur` | Monthly minimum wages, euro and purchasing power, by half-year |
| Eurostat dissemination API | `earn_nt_net` | Gross, income tax and employee social contributions at the EU low-wage benchmark |
| BIBB | file-existence probe | Whether a newer year of training allowances has been published |

The deduction percentage is computed from the published **tax and social
components**, never from Eurostat's NET figure — for Malta, Portugal, Greece and
Poland that NET does not reconcile with gross minus deductions, and we could
never explain why. That decision is now enforced in code rather than remembered.

### What it does, and what it deliberately does not

It updates `src/_data/europe.json` and opens a **pull request**. It does not
publish. A figure that changed may also make a sentence wrong, and no script can
see that — so the PR body lists every old figure that still appears anywhere in
the file, which is almost always prose contradicting its own table.

That check earns its place. Testing it against a deliberately stale Romania
caught the sentence *"Romania's minimum wage rose from €795 to €825"* — exactly
the kind of line that would otherwise have survived a figures update and
quietly contradicted the table beside it.

### Two bugs found while building it, both worth recording

**The frequency dimension is not the same in the two datasets.** `earn_mw_cur`
uses `S` (semi-annual) and `earn_nt_net` uses `A` (annual). Naming it produced
"no complete period found" and would have failed silently as a warning rather
than an error. The reader now leaves unnamed dimensions at their first value,
with a comment saying why.

**A plain substring search for an old figure reports false positives.** Checking
for `1233` matched inside *"Directive (EU) 2024/1233"*. The match is now
anchored so a number is only reported when it appears as a value in its own
right. This is a small thing, but a checker that cries wolf is one nobody reads
— the same rule the link checker was rewritten under on 2026-08-27.

### Verified behaviour

Run against the live API on 2026-10-29: minimum wages current for **2026-S2**,
tax and social contributions current for **2025**, no changes proposed. The
change path was tested by perturbing Romania back to its January figures; the
checker detected both the wage and the deduction change, rewrote the derived net
and purchasing-power figures correctly, dated the file, and flagged the stale
sentence.

### Cost

Nothing. GitHub Actions is free on public repositories, the checker installs no
dependencies, and it runs twelve times a year.

**The trap, and it is the reason this section exists.** Those hour ranges are
published with the stated assumption that the learner's **first language is a
European one**. Nepali is not. Quoting "260–490 hours" to a Nepali reader as
though it applied to them would be precisely the error this file keeps
recording: taking a general figure and applying it to a specific case it was
never measured on.

The page therefore gives the Goethe range, states plainly that it is not written
for this reader, and says to treat it as a **floor rather than an estimate**. It
does not invent a Nepali-specific number, and it asks readers who have done it
to send theirs — which would be one of the most useful figures on the site.

### Two gates, not one

The structural finding is that every country has **two** language questions with
very different answers: what you need to get in, and what you need to stay. The
page is built as a two-column table on exactly that split.

**Malta is the case that justifies the two-column design.** It has *no* language
gate to arrive — English will do — and a *Maltese* gate to settle. Wide open at
one end, shut at the other. A reader looking at a single "language" column would
have seen "English" and drawn exactly the wrong conclusion about where it leads.

### The trade-off the page now states outright

The countries with no language gate are, almost exactly, the countries with no
qualification at the end, permits tied to one employer, and the weakest rights
on the page. The one route that ends in something portable asks for B1 German
first.

The page says that is not a coincidence — the language requirement is part of
what makes the destination worth reaching — and frames the real choice as:
**spend the year on German and get a qualification, or skip the year and get a
job.** Both legitimate; only one usually explained.

It also says, because it is true and rarely said, that **a year of lessons you
will not pass is the most expensive thing on this page** — more than most agents
charge, and it costs the year as well.

### Why this belongs on a site that exists to promote the German route

It does not promote it. It sets out the single biggest reason a reader should
**not** take it, in a section of its own, above the money. A reader for whom
German is genuinely not achievable is better served by being told so in month
one than by discovering it after paying for a year of classes and missing the
exam queue twice.

The standing risk on this project has always been that a site written by someone
who believes in the route oversells it by omission. Leaving language out was an
omission of exactly that kind, and it survived eleven pages and a twelve-country
comparison before somebody who has actually met these students noticed.

### Open

- **What it really takes a Nepali first-language speaker to reach B1 German.**
  No published figure exists. This is the most valuable gap on the page and the
  page asks readers to fill it.
- Germany's and Austria's language requirements for permanent residence. Not
  checked.
- Greece and Cyprus rest on law-firm summaries rather than statutes.
- Bulgaria's position rests on a 2018 survey.
- Whether Malta's Maltese-language requirement for long-term residence has any
  exemption for English speakers. We found none, which is surprising given
  English is an official language — so it is marked unresolved rather than
  settled.

**Carried onto the start page the same day.** The start page said *"The exam
queue is the real bottleneck, not your German."* That is true for people who can
learn German and quietly assumes everyone can. A paragraph now follows it saying
that for some people the German itself is the bottleneck, that this is a real
answer rather than a failure, that B1 is 260–490 taught hours and that estimate
is a floor for a Nepali speaker, and that a year of lessons you will not pass
costs more than most agents charge plus the year. It links to /europe/ and ends
on the trade-off: the countries that ask for no language are almost exactly the
ones where the work leads nowhere.

The original sentence stays, because the exam queue *is* the bottleneck for most
readers. It is now one of two bottlenecks rather than the only one.

## The site is bilingual — Nepali mirror added, 2026-10-30

**What was added.** A Nepali version of every page at `/ne/…`, a language
switch in the navigation on both sides, and `hreflang` pairs so the two
versions read as one page in two languages rather than as duplicates.

**Why, and the argument that settled it.** The first proposal here was a short
Nepali summary of two or three pages rather than a mirror, on the grounds that
a machine translation of 34,000 words is 34,000 words of claims nobody has
checked. That was the wrong trade. The person who hands over seven to sixteen
lakh is often a parent who does not read English, and a parent deciding where
to send their child needs the wage tables, the queue figures and the statute
references — not a warning leaflet. Giving Nepali readers the caution while
keeping the information in English is the wrong way round.

**What is NOT claimed.** No page has been checked by a Nepali speaker. Every
Nepali page carries a notice at the top saying so in Nepali, naming the English
page as authoritative and linking to it. The front matter field
`translationState` is `machine` on all of them and becomes `checked` only when
a Nepali speaker has read one, with `checkedBy` and `checkedDate` recorded.

**How drift is prevented.** Each Nepali page records `sourceHash`, a hash of
the English text it was made from. `src/_data/translations.js` recomputes that
hash at build time; when the English page is edited the Nepali page
automatically tells the reader it has fallen behind, and
`scripts/check-translations.mjs` fails the run so it reaches a maintainer.
Verified by editing a figure on the English start page and watching the Nepali
page switch to the drift notice, then revert.

**What the checker proves, and what it does not.** `npm run check-translations`
verifies, for every Nepali page: that the recorded hash matches the English as
it stands; that every German or statutory term in the English also appears in
the Nepali (Ausbildung, Vorabzustimmung, § 296a SGB III, Goethe, ÖSD, telc,
ECL, VHS, B1, Lebenslauf and the rest), because a reader must be able to
recognise those on a form; that every figure in the English appears in the
Nepali; and that internal links point inside the mirror rather than dropping
the reader into English mid-page. It cannot say whether the Nepali is any
good. Only a Nepali speaker can.

**Numerals.** The Nepali pages use Arabic numerals (1,200) rather than
Devanagari (१,२००). Every figure on this site exists to be checked against
something — a fee an institute quoted, a wage in a contract, a number on an
embassy page — and the reader should see the same shape on the screen as on the
document in their hand. It also lets the checker verify mechanically that no
figure was dropped or altered.

**Pages deliberately left in English.** The imprint and the privacy notice.
Both are German legal instruments whose exact wording is the point (§ 5 DDG,
§ 18 MStV), both are `noindex`, and a reader who needs them is checking a legal
detail rather than being persuaded. The Nepali pages link to the English ones.

**The Europe page was only partly translated at this point.** *(Superseded the
same day — see the two entries below. It reached 100% before any of this was
committed. Kept because the mechanism it describes is still how that page
works.)* `/europe/` is a thin template over `src/_data/europe.json`, which
holds about 14,900 words — more prose than any other page on this site. The
Nepali page lays `src/_translations/europe.ne.json` over that data field by
field and falls back to English for anything not yet translated, so the page
works from the first line of translation rather than needing all of it.
Translated at this point: the language section, the single-permit rights,
long-term residence, all six scam patterns, and every country name, headline
and qualification answer — which is what the comparison table is made of.
Still English at this point: the money section (~4,500 words) and the
per-country detail (~6,600). `check-translations.mjs` prints the percentage
every run so the gap is a number rather than something a reader discovers.

**One behaviour change on the English side.** `src/assets/contact.js` now takes
its wording from `data-` attributes on the form instead of English string
literals, defaulting to the same English text, so the English page is
unchanged. This was necessary because the contact page promises that whether
you ticked the publish box "is written into that email in plain words, so you
can see it before you send". For a Nepali reader an English consent line breaks
that promise, so the Nepali form writes the permission line in Nepali and
English together.

**Weekly check.** `.github/workflows/translation-check.yml` runs the checker on
every push that touches a page and weekly on Mondays at 07:15 UTC, and opens an
issue labelled `translation-drift` naming the exact page and figure, closing it
again when the mirror is back in step.
