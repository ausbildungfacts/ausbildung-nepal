# Sources

Every factual claim on this site has a line here: what is claimed, where it came
from, and when it was last checked. If a claim has no line, it should not be on
the site.

**Why this file exists.** Readers plan a year of their life around these facts.
A wrong claim here is not a bad look, it is real damage. This file makes a wrong
claim findable instead of invisible.

## Status key

- **VERIFIED** — read on the primary source named
- **SECONDARY** — from a reliable report, not the primary source itself
- **OPEN** — asked, awaiting an answer. Must not be stated as settled on the site.

## Link checker, 2026-08-22

`scripts/check-links.mjs` plus `.github/workflows/link-check.yml`. Runs every
Monday 07:00 UTC and on demand. **Zero npm dependencies and no AI in the loop**,
so it costs nothing per run and there is no package that can rot or be
compromised.

**Result of the first real run: 24 external links across 11 pages, all alive, no
broken internal links or missing images.**

### The design decision that makes it useful

A checker that cries wolf gets ignored, so failures are graded:

| Response | Treated as | Why |
| --- | --- | --- |
| 404, 410, DNS failure, refused connection | **Dead — fails the run, opens an issue** | The page has genuinely gone |
| 401, 403, 405, 406, 429, 5xx, timeout | **Warning only — never fails** | Bot protection or a server wobble, not link rot |

This distinction is not theoretical. `frankfurt.de` answers **403 to
command-line requests** while serving the page normally to a browser. Treating
that as a dead link would have produced a false alarm on the single most-cited
authority page on the site.

Two further guards against noise: the checker sends a real browser User-Agent
(which is what gets `frankfurt.de` to answer 200), and every failure is retried
once after 1.5 seconds before being believed.

### How the notification works

On failure it opens a GitHub issue labelled `link-rot`, titled "Link check: a
cited source has gone", listing each dead URL **and which pages cite it**. If an
issue is already open it comments instead of opening a duplicate. When the links
resolve again it comments and closes the issue — so an open `link-rot` issue
always means something is broken *right now*. GitHub emails on both the issue and
the failed run.

### Verified, not assumed

The failure path was tested against a fixture containing a real 404, a
non-existent domain, a broken internal link and a missing image. All four were
caught, `mailto:` and `#fragment` links were correctly skipped, and the run
exited 1. The passing path exits 0.

### Known limitation

GitHub disables scheduled workflows in a repository after 60 days with no commit
activity. A site that is finished and correct could therefore go quiet exactly
when nobody is watching it. GitHub emails the owner when this happens; any commit
or a manual "Run workflow" revives it.

**Deliberately separate from `deploy.yml`** so that a flaky external site can
never block publishing.

### Two errors caught in the first version, both mine

**"Registered in Germany as a gGmbH" was wrong**, and it had been wrong in this
file since 22 August. NSST is registered **in Nepal**; the gGmbH is the German
*equivalent* their own document offers as a comparison. Stating the comparison as
the fact is the same move as the ÖSD mistake — a true general statement
substituted for the specific one nobody checked.

**"They pay for the classes and exams" was the right answer for the wrong
reason.** The first draft hedged it as *"what has been described to us"*, which

**employer** pays €3,000, and that fee covers the preparation, the language

working exactly as intended — a fee from the employer and from nobody else. It is
also the single most useful thing on the page for a reader being quoted 7 lakh,
because it shows the same costs being carried by the company.
